Codebase triage eliminates two-thirds of the Java repository

Inspecting all 21 Java files reveals that the core clinical algorithm is tightly concentrated. Nearly 39% of the repository consists of deferred Android UI, charting wrappers, and commented-out legacy classes (OfflineRecorderOld, Unused, and orphaned PrepareFragment helpers).

Another surprise sits inside MeasureFragment.java: despite being a UI fragment (1,123 lines), it houses the entire measurement state machine inside its inner SendSignal class alongside ~770 lines of Android view bindings and commented clinical test filename arrays. Extracting that orchestration cleanly is the primary architectural unlock for Raspberry Pi.

How the three-stage DPOAE signal pipeline operates

Commercial OAE earbuds and this Android app both rely on the same cochlear biophysics: presenting two pure primary tones (f1 and f2 with ratio f2/f1 ≈ 1.22) simultaneously into a sealed ear canal evokes a faint nonlinear cubic distortion product at 2f1 − f2 from healthy outer hair cells. Crucially, SignalGenerator.sine2speaker() routes f1 strictly to the Left speaker channel and f2 strictly to the Right speaker channel so the two tones mix acoustically inside the ear canal rather than electrically inside a single speaker transducer, preventing false hardware intermodulation.

1. Probe seal & occlusion check

Optional pre-check (CHECK_FIT)

Plays a looped 226 Hz tone (or pre-recorded chirp) while OfflineRecorder.envCheck() computes an attack/release time-domain envelope (or 50-bin moving average over FFT bins 64–640). Passes once 25 consecutive read buffers stay strictly inside [200, 500] (SEAL_CHECK_THRESH to SEAL_OCCLUSION_THRESH).

2. In-ear acoustic calibration

Optional gain solver (VOL_CALIB)

Plays a 0.1 s linear chirp preamble (1–4 kHz) followed by eight 0.2 s calibration tones (f1, f2 for all 4 pairs). Utils.volcalib() aligns capture latency via FFT cross-correlation, extracts 0.1 s windows (0.05 s padded), estimates SPL via p1·amp + p2, and solves a·exp(b·target_rx) for 65/55 dB SPL targets.

3. Coherent averaging & SNR

Core clinical screening loop

For each enabled pair, plays f1/f2 for 5 s (CONSTANT_TONE_LENGTH_IN_SECONDS), trims the first 1 s transient (48,000 samples), and coherently averages the remaining 1 s blocks. Rejects noisy segments where broadband artifact jumps ≥ 4 dB or SNR drops, then evaluates 2f1−f2 SNR against ±200 Hz sidebands (±2 Hz guard).

Target C++20 architecture decouples real-time audio from DSP

In the Android app, MeasureFragment starts separate OfflineRecorder and AudioStreamer threads and coordinates them with coarse Thread.sleep() calls while mutating static fields in Constants. On Raspberry Pi Linux, we eliminate all shared mutable globals and split the port into six cleanly isolated C++20 modules with a single deterministic full-duplex audio callback.

1. oae_config — Config & Hardware Profile

Replaces Constants and SettingsFragment preferences

Replaces static globals and Android SharedPreferences with an immutable OaeConfig struct loaded from JSON (nlohmann/json). Stores sample rate (48,000 Hz), active frequency pairs, SNR/artifact/noise thresholds, and a per-hardware calibration block (p1, p2, a, b, default/max Tx gains) keyed by audio interface/probe ID rather than Build.MODEL.

2. signal_gen — Stimulus Synthesizer

Replaces SignalGenerator and AngularMath

Pure stateless C++ functions generating interleaved stereo std::vector<int16_t> buffers: make_dual_tone(f1, f2, v1, v2, n_frames), make_linear_chirp(f0, f1, dur, scale), and make_calib_sequence() (4,800-sample pad + 0.1 s chirp + 8 sequential 0.2 s tones). Uses std::fmod instead of AngularMath.Normalize loops.

3. dsp_engine — FFTW3 Analysis Core

Replaces Signal and missing SignalProcessing JNI calls

Replaces all missing native-lib JNI calls with reusable FFTW3 (fftw_plan_dft_r2c_1d / fftw_plan_dft_1d) plans. Implements compute_power_spectrum(), xcorr_fft(), calc_snr(), calc_artifact_db(), and analyze_tone_recording() (1 s trim, coherent 1 s averaging, artifact rejection, OAE vs. IMD check).

4. calibrator — Fit Check & SPL Solver

Replaces Utils and fit logic from OfflineRecorder

Encapsulates the two pre-test checks: FitChecker (streaming attack/release envelope or chirp FFT bin-window moving average requiring 25 consecutive in-bounds frames) and VolumeCalibrator (chirp cross-correlation alignment, 0.1 s tone window extraction, SPL linear fit, exponential Tx gain update with safety clamping).

5. audio_engine — Full-Duplex Linux Audio

Replaces AudioStreamer and OfflineRecorder I/O

Built on ALSA (libasound) directly or PortAudio (ALSA backend) configured for hardware device hw:X,0 (bypassing PulseAudio/PipeWire resampling and AGC). Runs a full-duplex callback transferring stereo Tx and mono Rx frames via lock-free ring buffers so playback and capture start sample-synchronously.

6. session_runner — Headless CLI & Logger

Replaces MeasureFragment.SendSignal and FileOperations

Drives the deterministic state machine: IDLE → FIT_CHECK → VOL_CALIB → MEASURE_PAIR[0..3] → EVALUATE → SAVE. Outputs structured JSON results (per-frequency signal, noise, SNR, ambient noise, Pass/Refer verdict, noisy-band retry flag) plus standard 16-bit WAV files (replacing multi-megabyte plain-text integer dumps).

Phased porting plan verifies DSP parity before touching hardware

The fastest way to introduce silent clinical errors when porting DSP code is to rewrite the math and the audio hardware layer simultaneously. The six-phase schema below validates bit-level math parity offline on x86/ARM using recorded waveforms before integrating Raspberry Pi ALSA audio and acoustic coupler calibration.

Five bugs and hardware traps to fix during the C++ port

A blind line-for-line translation of the Java source will carry over two logic bugs and three platform assumptions that break on Raspberry Pi. Address all five explicitly during Phases 2–6.

ampCheck() never resets its accumulator

Logic bug in Signal.java (lines 12–28)

Inside ampCheck(), the loop resets counter = 0 every 1,000 samples but never resets summer = 0, and it sums signed 16-bit samples rather than magnitudes. Decide early whether to fix this to true windowed RMS/mean-abs (recommended) or preserve a legacy toggle for regression comparison.

checkfit() leaves playback null on unknown devices

Device guard bug in MeasureFragment.java (lines 941–951)

When calibSig is "tone" (the default), checkfit() only instantiates AudioStreamer when Constants.phone equals "sch" or "sch2"; otherwise it sets sp = null and throws a NullPointerException on sp.play(-1). Always load fit-check gain from the JSON hardware profile.

Missing native-lib FFT scaling & xcorr convention

NDK dependency in SignalProcessing.java and Utils.java

Because the Android NDK C++ source is not in the Java zip, verify FFT normalization directly: Signal.work() squares fftnative output before 10·log10, while Utils.compute() takes 20·log10—confirming fftnative returns linear unnormalized magnitudes. Also replace Utils.transform_idx(maxidx, sig_len) with standard linear zero-padded FFT cross-correlation so latency math is transparent.

Hardcoded smartphone SPL polynomials will not transfer

Acoustic mismatch in Utils.java (lines 188–227)

The p1_arr, p2_arr, a_arr, and b_arr arrays are empirical regressions measured on specific Android handsets (Galaxy S9, Pixel 3a XL, Doogee S96Pro). Running them on a Raspberry Pi audio HAT will produce wrong SPL levels and risk over-driving the probe speakers—Phase 6 coupler calibration is mandatory.

Hardware note for Raspberry Pi: never use the Pi's built-in 3.5 mm PWM audio jack (high noise floor, no mic input). Pair the C++ engine with an I2S HAT (such as HiFiBerry DAC+ ADC Pro) or a class-compliant 24-bit USB audio interface with true independent L/R headphone drivers and a low-noise mic preamp.

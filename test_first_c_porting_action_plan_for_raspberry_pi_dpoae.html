Test-First Action Plan for Porting DPOAE to Raspberry Pi C++

Start by writing five C++ behavioral test suites that encode the exact math, thresholds, and state transitions of the Android Java code—compiling against stub interfaces before a single line of production DSP or miniaudio I/O is written. Each subsequent step turns one test suite green until the full headless binary runs on your UGREEN 80864 USB adapter.

8 Steps
Step 1 locks down 5 C++ test suites mimicking Java behavior; Steps 2–6 turn them green offline; Steps 7–8 bring up Raspberry Pi hardware.

Step 1: Build the C++ test harness mimicking Java behavior

Before porting any implementation logic, initialize the CMake (C++20) project with stub headers for all six modules and write five standalone GoogleTest (or Catch2 v3) suites. To guarantee exact parity, generate golden input/output fixtures for pure-Java routines (or synthesize deterministic 48 kHz test waveforms with known SNR, delay, and artifact spikes) and run ctest to confirm every test compiles and fails cleanly ("red") against the stubs.

Why MockAudioEngine is essential in Step 1

Enables 100% deterministic CI on your laptop or Raspberry Pi

Define a minimal virtual interface IAudioEngine with two methods: run_duplex_fixed(tx_stereo, rx_mono_out) for calibration and 5 s tone captures, and run_duplex_streaming(tx_loop_stereo, on_rx_chunk) for continuous fit-checking.

In Step 1, MockAudioEngine implements IAudioEngine in memory by feeding pre-baked synthetic or recorded ear-canal signals back into rx_mono_out. In Step 7, MiniaudioEngine implements the exact same interface over ALSA + UGREEN 80864 without changing a single line of DSP or state-machine code.

Steps 2–8: Sequential porting roadmap from green tests to hardware

Execute each step strictly in order. Do not advance to the next step until the verification command for the current step passes with zero warnings or test failures.

Exact commands to kick off Step 1 on Linux or Raspberry Pi

You can complete Steps 1 through 6 on any Linux desktop, WSL2 instance, or directly on the Raspberry Pi before plugging in the UGREEN 80864.

  1. Install build & DSP packages: Run sudo apt install cmake g++ libfftw3-dev libasound2-dev (and vendor single-header miniaudio.h and toml.hpp into third_party/, plus FetchContent for GoogleTest in CMakeLists.txt).
  2. Create stub headers & Step 1 tests first: Define include/oae/*.hpp with empty function bodies returning dummy values, then write all five tests/test_*.cpp files and verify cmake -B build && cmake --build build && ctest --test-dir build --output-on-failure compiles cleanly and reports expected red failures.
  3. Lock down bug parity choices up front: In test_dsp_engine.cpp, explicitly assert the corrected windowed mean-abs ampCheck() (fixing Java's missing summer = 0 reset) and confirm whether you want a CLI flag (--legacy-amp-check) only if you plan to compare against old Android logs.
